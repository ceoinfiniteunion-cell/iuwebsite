## 1. Жёсткие правила

1. **Дизайн переносится точь-в-точь.** Всё, что есть в дизайне (секции, тексты, анимации, 3D, прелоадер, переходы, курсор, зерно, шторки, стопка портфолио, футер), должно быть на боевом сайте и выглядеть так же. Не «улучшать» и не упрощать дизайн по своему вкусу. Если что-то технически невозможно — записать в отчёт с причиной и ближайшим решением.
2. **Тексты — из нового дизайна.** Источник правды для текстов: то, что рендерит дизайн (главная — разметка `IU Home v2.dc.html`, остальные — `content/*.json` в шаблоне `IU Page.dc.html`). Старые тексты сайта не возвращать.
3. **Исключение — политика конфиденциальности:** текст берётся **дословно** с текущего сайта `services/privacy/index.html` (живая версия https://infiniteunion.com.ua/services/privacy/), оформляется в новом дизайне (шаблон `isArticle`).
4. **Никаких выдуманных фактов.** Цифры, цены, кейсы, отзывы — только из дизайна и `docs/FACTS.md`. Если дизайн противоречит FACTS.md — не править молча, записать в отчёт.
5. **Все текущие URL сохраняются.** Ни одна страница из `scripts/pages.json` и `sitemap.xml` не должна отдавать 404. Старые редиректы (`cfg.redirects` в `pages.json`) — сохранить.
6. **Бэкенд не ломать.** На Railway — только чтение (статус, логи, переменные без вывода значений секретов) и тестовая заявка. Менять env/код бэкенда — только то, что прямо указано в п. 6.4.
7. **Работать в ветке**, `main` не трогать до финальной проверки.
8. Не останавливаться на вопросах по мелочам: решить разумно, записать решение в `REDESIGN_REPORT.md`. Остановиться и спросить Єгора только перед: push в `main`, изменением env на Railway, удалением чего-либо в бэкенде.

## 3. Этап 1 — архитектура продакшна

Прототипы `.dc.html` — это Design Components (рантайм `support.js`, `fetch` контента, `{{ }}`-шаблоны). На прод так нельзя: текст должен быть в исходном HTML (SEO), без лишнего рантайма.

Сделать статическую генерацию (SSG), как описано в DESIGN_SYSTEM §10:

1. Генератор `scripts/render-design.mjs` (Node, без фреймворков) → для каждой страницы пишет `/<path>/index.html` с **полным текстом в разметке**.
   - Рекомендуемый путь: рендерить прототип в Playwright (`?p=<ключ>`), брать финальный DOM, а затем приводить его в порядок: убрать DC-рантайм, `{{ }}`, `data-dc-*`, `style-hover`/`style-focus` перевести в CSS (`:hover`/`:focus-visible`), инлайн-стили вынести в CSS-классы на токенах из DESIGN_SYSTEM §2. Если чище писать шаблоны вручную по JSON — допустимо, главное — визуальный результат 1:1.
   - Ссылки: `IU Page.dc.html?p=services__bots` → `/services/bots/`, `en__home` → `/en/`, `IU Home v2.dc.html` → `/`, `IU 404.dc.html` → `/404.html`.
2. CSS: `src/css/` → минифицированный `assets/css/site.[hash].css`. Критический CSS первого экрана — инлайн в `<head>`, остальное — неблокирующе.
3. JS: вся анимационная логика из `frame()` → один модуль `assets/js/motion.[hash].js` (A1–A15, шторки, портфолио-стопка, прогресс, вуаль переходов, счётчики, курсор, зерно), подключение `defer`/`type=module`. Один rAF на страницу, в rAF сначала все чтения `getBoundingClientRect`, потом все записи стилей (без layout thrash). Запись стилей только при смене состояния.
4. 3D (`iu-snake.js`, `iu-glyph.js`, three r185, GLTF/Draco) — отдельные чанки, грузятся **лениво** только на страницах, где нужны, после первого рендера (`requestIdleCallback` / после прелоадера). На страницах без 3D three.js не грузится вообще.
5. Старые файлы, которые больше не используются (`snake.js`, `globe.js`, `orbit.js`, `hero.js`, `cobe.umd.js`, `mobile.css`, `main.css` старого дизайна, `vendor/gsap` если не нужен, старые `three.min.js` r-старые), удалить из сборки и из репо (в git история останется, тег бэкапа есть).
6. Хеши в именах ассетов (cache-busting под Cloudflare).
7. Обновить `scripts/build-site.mjs`, `scripts/check.mjs`, `scripts/sitemap.mjs`, `scripts/pages.json`, `package.json` scripts, линтеры (`.htmlvalidate.json`, `.stylelintrc.json`, `eslint.config.js`), e2e-тесты и `.github/workflows/*` под новую структуру, чтобы CI был зелёным.

## 4. Этап 2 — перенос страниц

Порядок: (1) общие слои и компоненты → (2) главная → (3) шаблон услуги на одной странице `services/websites` → сверка → (4) все остальные UA-страницы → (5) EN → (6) блог → (7) pricing, portfolio → (8) privacy → (9) 404.

Для каждой страницы обязательно:
- Все секции из дизайна в том же порядке, те же тексты, та же типографика, отступы, цвета, свечение.
- Все анимации из каталога DESIGN_SYSTEM §4 работают так же (тайминги, easing, пороги).
- Главная: прелоадер INFINITE, 3D-змея в хиро с позой от скролла и fallback-уроборосом, стопка портфолио с физикой пружин, «Наш підхід» со словами, пайплайн, AI-конструктор, Ad Tracker, тикер, футер с бегущей строкой.
- Внутренние: 3D-символ в хиро по таблице DESIGN_SYSTEM §6.1, визуал семейства, шторки секций, прогресс-бар, вуаль переходов между страницами.
- 404: глитч-цифры, змея, быстрые ссылки, реальный HTTP 404 (GitHub Pages отдаёт `404.html`).
- Портфолио: заменить **все** mShots (`s0.wp.com/mshots/...`) на свои скриншоты в `/assets/` (снять Playwright-ом с реальных сайтов 1440×990 после полной загрузки, сжать в AVIF + WebP, `width/height`, `loading="lazy"`, описательный `alt`). `shot-gym4fit.png` (1.4 МБ) — тоже пережать.
- Контакты: ссылки на Telegram менеджера, канал, WhatsApp, телефон, Viber (если в дизайне 4 мессенджера — как в дизайне). **Email:** в дизайне `supportinfiniteunion@gmail.com`, на текущем сайте может быть `ceoinfiniteunion@gmail.com` — сверить с текущим сайтом и FACTS.md, при расхождении оставить как на текущем сайте и записать в отчёт.

**Проверка «точь-в-точь»** (автоматически, для каждой страницы и ширины из этапа 0): Playwright-скриншот собранной страницы vs эталон из `design/baseline/` через `pixelmatch`. Анимации для снимка заморозить в конечном состоянии (флаг `?static=1` или эмуляция reduced-motion только в тесте), 3D-canvas маскировать. Порог отличий ≤ 1–2 % пикселей; всё, что выше, — чинить или объяснить в отчёте. Сводная таблица в отчёте.

## 6. Форма заявки → Telegram-бот

### 6.1 Подключение
Все формы (главная + CTA-блоки на всех страницах, UA и EN) отправляют на существующий бэкенд **точно так же, как сейчас** в `src/js/ui.js`:
- `POST https://api.infiniteunion.com.ua/lead`, `Content-Type: application/json`, таймаут 10 с (AbortController).
- Тело: `name` (cn), `contact` (cc), `phone` (cphone), `project_type` (ctype), `budget` (cbudget), `deadline` (cdeadline), `project` (cp), `idempotency_key` (crypto.randomUUID).
- Значения `<option>` в `ctype` и `cbudget` — сверить с тем, что принимает бэкенд (посмотреть валидацию в коде бэкенда/логах Railway). Если в дизайне другие варианты — подогнать значения, сохранив тексты дизайна.
- Honeypot-поле `website` (скрыто визуально и от скринридеров, `tabindex=-1`, `autocomplete=off`).
- Клиентский лимит: 1 отправка в 30 с (sessionStorage).
- Валидация: обязательные поля, телефон/юзернейм, понятные ошибки в стиле дизайна.
- Успех: состояние «отправлено» как в дизайне + `dataLayer.push({event:'form_success'})` + `gtag('event','conversion',{send_to:'AW-18360841103/YwDACNqs1tocEI_nkLNE', value:1.0, currency:'UAH'})`.
- Ошибка/таймаут: тост в стиле дизайна + предложение написать в Telegram.
- Кнопка блокируется на время отправки, двойной клик не создаёт две заявки.

### 6.2 Проверка бэкенда (Railway CLI)
1. `railway status`, `railway logs` (последние ошибки), `railway variables` — **значения секретов в вывод/отчёт не печатать**, только имена.
2. Проверить CORS: `https://infiniteunion.com.ua` и `https://www.infiniteunion.com.ua` разрешены, локальный origin для теста — временно не добавлять в прод, тестировать через curl.
3. `curl` на `/lead` с тестовыми данными: имя `ТЕСТ — Claude Code, ігнорувати`, контакт `@test`. Ожидается 2xx. Проверить в логах Railway, что заявка записалась и ушла в Telegram. **Попросить Єгора подтвердить, что сообщение пришло в бот.**
4. Негативные тесты: пустое тело → 4xx, honeypot → тихо игнорируется, повтор с тем же `idempotency_key` → без дубля.

### 6.3 E2E
Playwright-тест формы: с замоканным API (успех, ошибка, таймаут) на главной и одной внутренней странице, на 390 и 1440. После деплоя — одна реальная тестовая заявка с живого сайта.

### 6.4 Что можно поменять на Railway (только после согласия Єгора)
- Если `RATE_LIMIT` всё ещё `9999` — предложить вернуть разумное значение (например 3–5 в минуту на IP).
- Если эндпоинт `/generate` (LLM) открыт без защиты — доложить и предложить закрыть (ключ/rate limit/origin).

## 7. SEO (не потерять ничего, только улучшить)

Для **каждой** страницы:
- `<title>` ≤ 60 символов, ключ в начале; `description` 140–160 символов (цена «від» + місто + УТП) — из дизайн-контента; если превышает лимиты — подрезать, не меняя смысл.
- Одна `H1` с главным ключом, H2 — вторичные ключи, логичная иерархия без пропусков.
- **Весь текст в исходном HTML** (проверка: `curl` страницы без JS содержит H1, все H2, тексты FAQ, цены, кейсы). Анимации прячут только визуально (clip-path/opacity), не `display:none` для контента.
- Счётчики: в разметке финальные числа, `data-count` для анимации.
- `canonical` (с конечным `/`), `hreflang` uk / en / x-default — только между реально существующими парами страниц, взаимные.
- Open Graph + Twitter Card, `og:image` 1200×630 (≤ 300 КБ) для каждого типа страниц.
- JSON-LD в `<head>`: `ProfessionalService` (Харків, geo 49.983/36.233, areaServed, телефон, email, sameAs, `hasOfferCatalog` с `minPrice`) на главной; `WebSite`; `BreadcrumbList` на внутренних; `FAQPage` где есть FAQ; `Service` на страницах услуг; `BlogPosting`/`Article` на статьях; `CollectionPage`/`ItemList` на portfolio. Валидировать (schema.org validator / Rich Results, без ошибок). В JSON-LD никаких `{{`/`}}`.
- `alt` у всех изображений, описательный. `width/height` у всех `<img>`.
- Внутренняя перелинковка: футер со всеми услугами, хлебные крошки, «Може зацікавити».
- `lang="uk"` / `lang="en"`. EN-страницы полностью на английском (проверить, что нет украинских кусков).
- `sitemap.xml` пересобрать (`lastmod` = дата деплоя), все индексируемые URL, без noindex-страниц и редиректов. `robots.txt` сохранить (+ строка Sitemap).
- Верификация Google Search Console (мета-тег или файл `google*.html`) — сохранить, если есть.
- GTM (+ noscript iframe с `title`), gtag AW на всех страницах. CSP (если задаётся мета-тегом) обновить: GTM, GA, Google Ads, doubleclick, Cloudinary (GLB), `api.infiniteunion.com.ua`, шрифты (если не self-host).
- Сравнение «до/после» по каждой странице в отчёте: title, description, H1, количество слов, есть ли главный ключ из `SEO_KEYWORDS.md`. Если в новом тексте главный ключ пропал из title/H1 — минимально вернуть и записать в отчёт.
- Заметка в отчёт (без изменения): в `robots.txt` заблокирован GPTBot — для видимости в ChatGPT/AI-поиске это минус; решение за Єгором.

## 8. Скорость и плавность (обязательные бюджеты)

Целевые показатели на **каждом шаблоне** (главная, услуга, pricing, portfolio, блог-статья, EN-главная, 404), Lighthouse mobile (эмуляция Moto G Power, 4G) и desktop:
- Performance ≥ 90 mobile, ≥ 95 desktop; SEO = 100; Best Practices = 100; Accessibility ≥ 95.
- LCP ≤ 2.0 с (mobile), CLS ≤ 0.05, INP ≤ 200 мс, TBT ≤ 200 мс.
- Вес первой загрузки без 3D: HTML+CSS+JS ≤ 200 КБ gzip. three.js + модель — только ленивой догрузкой.

Как добиться:
1. **Шрифты** Space Grotesk и JetBrains Mono — self-host woff2, сабсет латиница + кириллица, `font-display: swap`, `preload` для двух основных начертаний, fallback с `size-adjust`, чтобы не прыгал текст.
2. **Прелоадер** главной — показывать только при первом визите за сессию (sessionStorage), не больше 2 с, HTML страницы грузится параллельно; при возврате по истории (`pageshow` + bfcache) не показывать. На внутренних страницах прелоадера нет.
3. **3D:** `pixelRatio ≤ 1.75` (на мобиле ≤ 1.5), пауза при уходе canvas с экрана и при скрытой вкладке, `antialias` только на desktop. GLB змеи: `preconnect` к Cloudinary; лучше положить модель к себе в `/assets/3d/` (Draco) с долгим кешем. Draco-декодер — локальный.
4. **Слабые устройства** (`navigator.deviceMemory ≤ 4`, `hardwareConcurrency ≤ 4`, `saveData`, или стабильный FPS < 40 за первые 2 с): вместо живого 3D — статичный кадр (заранее отрендеренный AVIF змеи/символа), физику портфолио упростить. Внешне — тот же дизайн.
5. **`prefers-reduced-motion`**: выключить шторки, искру, физику портфолио (карточки сразу на местах), marquee, вуаль переходов; контент виден сразу.
6. Не анимировать `filter`/`backdrop-filter`/большие `box-shadow` на крупных блоках; анимировать только `transform`/`opacity`/`clip-path`. `will-change` — только на время анимации.
7. Изображения: AVIF/WebP + `srcset/sizes`, `loading="lazy"` всё ниже первого экрана, `fetchpriority="high"` для LCP-элемента.
8. **Service Worker:** текущий `sw.js` кеширует старые файлы (`main.css`, `snake.js`, `globe.js`…) — без замены вернувшиеся посетители увидят сломанный старый дизайн. Новый `sw.js`: новое имя кеша, удаление всех старых кешей при `activate`, network-first для HTML, cache-first для хешированных ассетов, Google-домены и `api.infiniteunion.com.ua` не перехватывать. Проверить сценарий «зашёл на старую версию → открыл новую» в Playwright.
9. Вуаль переходов между страницами — не блокирует переход, если JS упал; ссылки работают как обычные `<a href>`; `prefers-reduced-motion` её отключает.

## 9. Адаптив и кросс-браузерность

- Ширины: 360, 375, 390, 414, 430, 768, 820, 1024, 1280, 1440, 1920, 2560.
- Движки: Chromium, WebKit (Safari iOS — главный риск), Firefox — через Playwright (`devices['iPhone 14']`, `devices['Pixel 7']`, `devices['iPad Pro 11']`, desktop).
- Для каждой страницы и ширины автоматически проверить:
  - нет горизонтального скролла (`document.documentElement.scrollWidth <= innerWidth`);
  - нет ошибок в консоли и 404 ресурсов;
  - все кликабельные элементы ≥ 44×44 px на тач-устройствах;
  - текст не обрезан, числа не ломаются на две строки (`&nbsp;` + `nowrap`), таблицы скроллятся внутри рамки.
- iOS Safari: `100vh` → `100svh`/`100dvh` для sticky-сцен, `backdrop-filter` с `-webkit-`, `input type=date` в тёмной теме, отсутствие зума при фокусе (font-size полей ≥ 16px), безопасные зоны (`env(safe-area-inset-*)`).
- Бургер-меню на весь экран (< 820px), блокировка скролла под ним, закрытие по Esc и по клику на ссылку.
- Курсорная подсветка и tilt выключены на touch.
- Клавиатура: видимый `:focus-visible`, порядок табуляции, skip-link «До контенту».
